| Field | Answer |
|---|---|
| Purpose | One public site for lean and differential attestation: a home page that states the claim, a benchmark page that shows the evidence, a quick start that gets a developer to a first verdict, docs that explain the rest, and the paper. Done means the five pages are served on GitHub Pages and the owner has walked them. |
| Success criteria | (1) From Home a developer reaches Quick start in one click and copies a first run that reproduces the shown output on a fresh clone. (2) Every leaderboard row says who measured it, on which version, over how many instances, with which judge, and links its source. (3) Every page of lean's docs/ and every DA architecture page is reachable from the docs sidebar and found by search. (4) One command builds the whole site; a push to main deploys it. (5) Every page shows at 390 px with no horizontal scroll. (6) The owner walked all five pages at both widths and signed the review. |
| Pivotal loop | Read the claim (Home) → see the evidence (Benchmark) → run it (Quick start) → learn it (Docs) → cite it (Paper). Missing any of the four new pages makes the site the one page it is today. |
| Residual | `Residual: open critical/HIGH rows + unmet REQUIRED rows + red gate checks + journeys not passing (of J1, J2, J3) = N` |
| Test plan | unit: `scripts/*.test.mjs` (markdown render, leaderboard schema), owner Cue, `node --test`, exit 0 · integration: the build produces one page per source (`scripts/build.mjs --check`) · functional: the link checker over the built site (`scripts/links.mjs`), red on any broken internal link · contract: `data/leaderboard.schema.json` validated by `scripts/check-leaderboard.mjs` · end-to-end: one headless Playwright test per journey (J1, J2, J3), written by app-tests, certified by journey-verifier, seen red at scaffold · acceptance: the owner's walk (row "Owner render review") · regression: links + journeys in CI on every push · performance: a page-weight budget check (`Perf-budget:` below) · smoke: the Pages URL answers 200 with the build's content marker · mutation: a leaderboard row stripped of its source turns the contract check red. Every runner is wired in CI and in `npm test`. |
